# 出口与API关联管理

版本v0.0.24，2026-10-27。目标是在真实用户环境中整理客户端可见出口、进程和具体HTTP请求；不更改产品或发起额外业务请求。

## 使用

打开 `/probe`，开始记录后在客户端操作，停止并统计。在“出口与API关联”按地址、PID或API路径查找，选择本地/远端范围，点击“查看API”在弹框查看请求方法、归一化路径、来源、关联依据、次数、RPM、峰值秒请求、响应头与完整耗时P50/P95及异常。进程表的API关联按钮也打开同一地址详情，保留列表上下文。导出出口/API生成带批次、时间和采集缺口的JSON。

## 证据分级

| 依据 | 能说明什么 | 不说明什么 |
| --- | --- | --- |
| NetLog绑定 | 同一请求生命周期内，`HTTP_STREAM_REQUEST_BOUND_TO_JOB`指向已满足请求的Job，`SOCKET_POOL_BOUND_TO_SOCKET`指向获得的Socket；该Socket在绑定前有成功`TCP_CONNECT_ATTEMPT`的`remote_address`，且未观察到随后关闭 | 网络栈记录PID不等于最初业务发起进程；不能自动穿透代理或零信任网关 |
| 页面响应对端 | 非缓存页面响应提供了远端IP及端口 | 不含OS Socket标识，不据此确认PID；对端可能是本机代理 |
| URL目标候选 | 捕获的方法/路径指向该服务地址 | 不证明连接成功、请求抵达、实际路由或进程归属 |
| 缓存响应 | 页面完成了一次缓存/ServiceWorker相关响应 | 不作真实后端访问证据 |
| TCP连接记录 | Windows采样发现此PID的远端连接状态，可能含连接尝试 | 不能得到API路径、请求数或后端业务成功 |
| UDP事件 | Chromium事件中可见该数字IP端点及日志PID | 不能转换成HTTP请求数或证明HTTP3 |

只跟随明确绑定链，拒绝按任意dependency图遍历；共享DNS、连接池或H2会话可能连接多个无关请求。未捕获Socket建立、连接失败、已关闭、绑定在请求窗口之外、HTTP2/QUIC未实现的链条都不提升为确定关联。旧汇总只派生URL目标候选，不重写历史文件或回填缺失证据。

## 计数和覆盖边界

- 页面与NetLog独立统计，不能相加；同一API的两种来源保留。
- 每个出口的请求数按实际落入该地址的请求子集计算，不把整组请求数分配给全部对端。重试涉及多个出口时不可跨出口简单累加。
- 有连接但无API记录显示“未获取”，不显示成0次后端访问。API组数只是已观察到的方法和归一化路径分组数。
- NetLog完整关联停止后生成。记录中的网络层尚未解析，缺口、丢弃、切段和不可用状态仍显示在原监控卡及导出文件中。
- Node.js原生HTTP、独立worker、IPC及代理后的最终出口仍有缺口。未知/动态路径段保持脱敏；不采集认证头、正文、查询参数、令牌或Cookie。
- 实际公网NAT出口、后端处理耗时、CPU和总容量不能由客户端对端表得出。DNS不额外解析，域名未解析时仍显示IP未知。

原生定义依据：[Chromium NetLog事件定义](https://github.com/chromium/chromium/blob/main/net/log/net_log_event_type_list.h)。HTTP_STREAM_REQUEST_BOUND_TO_JOB指向满足请求的Job，SOCKET_POOL_BOUND_TO_SOCKET指向获得的Socket；成功TCP_CONNECT_ATTEMPT提供remote_address。实现按可见字段降级，不以最新版文档假定当前Electron必有这些事件。

## 验证记录

18项定向测试通过。静置批次 `probe-1793077047041-034c904b-2a42-40c0-8f4d-d19b06a30385` 记录63.30秒：页面170次请求与NetLog165次请求分开统计，TCP/UDP各32轮采样；共6个地址，含本地网关、4个TCP远端和1个Chromium UDP端点。切段间隔703ms、0事件丢弃，保留部分采集状态。本批远端HTTP为0，未取得实际远端Socket绑定样本；绑定算法目前通过模拟事件和反例测试，不能说已实机验证远端全链路。

浏览器确认出口搜索与范围筛选、API弹框的来源和路径过滤、关闭返回列表及无API提示。旧15分钟批次的内网目标展示14个NetLog请求、2个归一化方法/路径组，明确为URL目标候选；该批仍为部分采集，不能估计完整频率。出口JSON已实际下载并核对批次、6个地址及历史派生/partial标志。未发现前端错误；未运行功能遍历或发起额外产品业务请求。
